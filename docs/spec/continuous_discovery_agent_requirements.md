# 要件定義: Continuous Discovery Agent MVP

## 1. はじめに

Continuous Discovery Agent MVP は、営業会話、日報、音声入力、コンサルタントメモ、競合情報などから定性的な業務知識を継続的に収集し、組織学習につなげるハッカソン向けプロダクトです。

MVP では完全な正確性よりも、知識を素早く形成し、検索し、関連づけ、後から訂正できることを優先します。AI が抽出した知識には誤りが混じり得るため、重い承認フローで止めるのではなく、事実・仮説・根拠・confidence を分けて扱います。

## 2. プロダクトビジョン

本プロダクトは、AI が経営判断を直接代行する「AI コンサルタント」ではありません。人間が気づきにくい変化を検出し、追加観測や意思決定の材料を増やす組織学習プラットフォームです。

中核ループ:

```text
観測
↓
ナレッジ形成
↓
発見
↓
仮説
↓
追加観測
↓
組織学習
```

## 3. MVP スコープ

MVP で扱う範囲:

- 初期アンケートと追加質問による企業理解の収集
- AI による KPI 候補、重点観測項目、追加質問の生成
- BigQuery への構造化データ保存
- BigQuery Graph 用の node / edge 生成
- LLM Wiki の生成と Cloud Storage への保存
- 月次発見レポートの生成と閲覧
- Report Copilot によるレポート確認
- Human-in-the-loop による重要候補の承認

MVP で扱わない範囲:

- AI による最終経営判断
- 本番レベルの厳格な権限管理
- 完全自動の本番反映
- 高負荷向けの最適化
- Terraform apply や production deploy の自動実行

## 4. 主要ユーザー

- 経営コンサルタント
- 中小企業診断士
- DX コンサルタント
- 支援先企業の経営者
- 営業責任者、店舗責任者、現場責任者

## 5. 機能要件

### 5.1 情報収集

- ユーザーは初期アンケートに回答できる。
- システムは回答を企業ごとに保存できる。
- AI は不足情報を検出し、追加質問を生成できる。
- 追加質問は回答しやすい粒度に分割される。

### 5.2 ナレッジ形成

- AI は回答や観測情報から企業プロフィールを生成できる。
- AI は KPI 候補と重点観測項目候補を生成できる。
- AI は観測事実と仮説を区別して保存できる。
- 生成結果には根拠と confidence を含める。

### 5.3 グラフ化

- 顧客、商品、課題、KPI、競合、観測、仮説を node として扱える。
- node 間の関係を edge として保存できる。
- フロントエンドは node / edge を取得して可視化できる。

### 5.4 Wiki

- AI は人間が読める LLM Wiki を生成できる。
- Wiki は `current` と `versions` に分けて保存する。
- 重要な更新は人間の確認対象にできる。

### 5.5 レポート

- システムは前月分の Monthly Discovery Report を取得または生成できる。
- レポートには事実、仮説、根拠、confidence、推奨観測を含める。
- レポートは Cloud Storage または local storage emulator に保存する。

### 5.6 承認

- KPI 定義や重点観測項目の本番反映には人間の承認を必要とする。
- 承認前の候補と承認済み定義を分離する。
- AI の自己申告だけで成功判定しない。

## 6. 非機能要件

- ローカル開発では BigQuery Emulator、filesystem storage fallback、Ollama を使える。
- AI 出力を downstream decision に使う場合は schema validation を通す。
- Secret Manager の値、API キー、サービスアカウントキーをリポジトリに置かない。
- Cost Guard を前提にし、高コスト操作は人間の承認を必要とする。
- Cloud Run は `min_instances=0` を基本とする。

## 7. 成功条件

- 初期回答から追加質問、Wiki、Graph、月次レポートまで一連の流れをローカルで確認できる。
- 保存済みレポートがある場合は再生成せず表示できる。
- 保存済みレポートがない場合は生成し、同じ保存先へ書き込める。
- AI が生成した候補を人間が承認する前提が保たれている。
- ドキュメントと実装の現状が大きく矛盾していない。
